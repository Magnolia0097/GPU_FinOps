# ADR-0005: ML은 베이스라인을 이겼을 때만 채택한다

- **상태**: 채택
- **일자**: 2026-09-14

## 배경

이 프로젝트에는 수요 예측이 포함된다. 그런데 지원 직무는 **데이터 엔지니어**이고,
면접에서 나올 질문은 정확도가 아니라 이것이다.

> "왜 여기에 머신러닝을 쓰셨나요?"

이 질문에 "요즘 많이 쓰니까" 또는 "정확도가 높아서"로 답하면 감점이다.
전자는 판단이 없다는 뜻이고, 후자는 **무엇보다 높은지**를 말하지 않기 때문이다.

동시에 실무에서 ML 도입 실패의 다수는 성능 문제가 아니라
**더 단순한 방법으로 충분했는데 쓴 것**이다.

## 결정

### 1. 베이스라인을 먼저 구현한다

| 베이스라인 | 정의 |
|---|---|
| `naive` | 직전 시각 값 |
| `seasonal_naive_168h` | 168시간(1주) 전 같은 시각 ← **주 베이스라인** |
| `moving_average_24h` | 최근 24시간 이동평균 |

### 2. ML은 베이스라인을 유의미하게 이겼을 때만 채택한다

- 판정 지표: **WAPE** (MAPE 아님 — 근거는 아래)
- 이기지 못하면 **베이스라인을 채택하고 그 사실을 기록한다**
- 기록된 "채택하지 않음"도 산출물이다

### 3. ML을 쓸 수 있는 지점을 사전에 한정한다

| 용도 | 정당화 논리 |
|---|---|
| **분위수 수요 예측** | 용량 조달은 평균이 아니라 **P90** 기준이다. 평균으로 조달하면 절반의 시간 동안 부족하다. → 점 예측으로는 애초에 답이 안 나오고, pinball loss가 필연적으로 요구된다 |
| **잡 실행시간 예측** | 스팟 중단 손실을 계산하려면 잔여 실행시간이 필요한데 제출 시점엔 알 수 없다. 규칙으로 대체 불가 |
| **비용 이상 탐지** | **단, 규칙 기반(STL 잔차 + z-score)을 먼저 시도하고 한계를 데이터로 보인 뒤에만** |

### 4. 금지 목록

- 정형 시계열에 딥러닝
- 특성 중요도를 설명할 수 없는 모델
- **LLM으로 숫자를 생성하는 것**

LLM을 리포트 요약에 쓸 경우, **숫자는 전부 SQL이 계산하고 LLM은 설명만 한다.**
이 경계는 코드 구조로 강제한다 — LLM 호출은 수치 생성 경로에 접근할 수 없다.

## 근거

1. **"왜 썼나"에 대한 답이 문서로 존재하게 된다.**
   비교표가 있으면 질문이 "왜 썼냐"에서 "이렇게까지 검증했냐"로 바뀐다.

2. **분위수 예측은 비즈니스 요구가 손실함수를 직접 규정한 사례다.**
   "P90이 필요하다 → 따라서 pinball loss" 는 논리가 끊기지 않는다.
   이런 종류의 정당화는 반박하기 어렵다.

3. **WAPE를 쓰는 이유가 데이터에 근거한다.**
   MAPE는 실제값이 0에 가까울 때 발산한다. GPU 수요는 야간·주말에 0에 근접한다.
   따라서 MAPE는 이 데이터에 부적합하다. **지표 선택에도 근거가 있다는 점 자체가 신호다.**

4. **ML을 버리는 것도 결과다.**
   "seasonal naive가 최선이었고 그래서 그것을 배포했다"는 결론은
   억지로 모델을 끼워넣은 프로젝트보다 성숙해 보인다.

## 검토한 대안

| 대안 | 장점 | 단점 | 기각 사유 |
|---|---|---|---|
| ML 먼저 구현, 베이스라인 생략 | 시간 절약 | 개선 폭을 증명할 기준이 없음 | **"왜 썼나"에 답할 수 없음** |
| 최신 시계열 모델(Transformer 계열) 도입 | 화제성 | 2개월 데이터로 과적합, 해석 불가, 8주 예산 초과 | 데이터 규모 대비 부적합 |
| 통계 모델(ARIMA/Prophet)만 사용 | 해석 용이 | 분위수 예측이 제한적, 다변량 피처 활용 어려움 | P90 요구를 충족하기 어려움 |
| 예측 없이 과거 실측만 사용 | 가장 단순 | L3 조달 최적화의 입력이 사라짐 | 처방 계층이 성립 불가 |
| LLM에게 예측을 시킴 | 구현 간단 | 재현 불가, 검증 불가, 근거 없음 | **비용 의사결정에 환각 리스크는 용납 불가** |

## 결과

**얻는 것**
- "왜 ML인가"에 대한 문서화된 답
- 지표 선택(WAPE)의 근거
- ML 미채택이라는 결론도 유효한 산출물이 되는 구조

**포기하는 것**
- 베이스라인 구현 공수 (약 1~2일)
- 모델 성능 자랑의 기회 — 베이스라인이 이기면 그렇게 기록해야 한다

**강제 규칙**
- 모델 비교표 없이 모델을 배포하지 않는다
- 비교표에는 베이스라인 3종이 모두 포함되어야 한다
- LLM 호출 코드는 수치 계산 모듈을 import할 수 없다

## 재검토 조건

- 데이터 기간이 늘어나 계절성 학습이 가능해지면 모델 후보를 재검토한다.
- 베이스라인이 모든 구간에서 승리하면 L2의 범위를 축소하고
  그 시간을 L3 민감도 분석에 재배분한다.
