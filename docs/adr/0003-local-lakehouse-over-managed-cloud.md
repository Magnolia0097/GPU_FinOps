# ADR-0003: 관리형 클라우드 대신 로컬 레이크하우스를 쓴다

- **상태**: 채택
- **일자**: 2026-09-14

## 배경

파이프라인을 실행할 인프라를 정해야 한다. 제약은 다음과 같다.

- 예산 0원
- 1인, 8주
- **1차 독자가 결과물을 직접 검증할 수 있어야 한다**

마지막 항목이 중요하다. 포트폴리오는 읽히는 것이 아니라 **확인되는** 것이다.

## 결정

로컬 Docker Compose 기반 레이크하우스를 구성한다.

```
MinIO (S3 호환) → Iceberg → dbt → Postgres → 대시보드
                      ↑
                  Airflow (오케스트레이션)
```

단, **가격 데이터만은 실제 AWS API에서 수집한다** (ADR-0004).
즉 "로컬 실행 + 실측 외부 데이터" 하이브리드다.

README에 **AWS 이관 매핑표**를 명시해 클라우드 이해도를 별도로 증명한다.

| 로컬 | AWS 대응 |
|---|---|
| MinIO | S3 |
| Iceberg on MinIO | S3 + Glue Catalog |
| 로컬 Spark / DuckDB | EMR / Athena |
| Airflow (compose) | MWAA |
| Postgres | RDS / Redshift |

## 근거

1. **재현성이 최고의 신뢰 신호다.**
   `docker compose up` 한 번으로 리뷰어가 전부 돌려볼 수 있다.
   "돌아간다고 주장하는 것"과 "돌려볼 수 있는 것"의 차이는 크다.

2. **8주 내내 무료다.**
   클라우드 과금은 프로젝트 중단 위험이다. 잔고가 떨어지면 데모가 죽는다.
   포트폴리오는 채용 과정 내내 살아 있어야 한다.

3. **클라우드 역량은 매핑표와 ADR로 증명 가능하다.**
   "S3를 써봤다"보다 "왜 MinIO로 대체했고 실제로는 무엇이 달라지는가"를
   설명하는 쪽이 오히려 이해도가 깊어 보인다.

4. **로컬이 디버깅이 빠르다.**
   1인 프로젝트에서 클라우드 왕복 시간은 그대로 일정 손실이다.

## 검토한 대안

| 대안 | 장점 | 단점 | 기각 사유 |
|---|---|---|---|
| **AWS 실과금 구성** | 클라우드 실무 경험 직접 증명, 채용공고 키워드 일치 | 월 비용 발생, **리뷰어가 재현 불가**, 잔고 소진 시 데모 사망 | 재현 불가가 결정적. 프리티어로는 Spark/EMR 규모를 감당 못 함 |
| GCP / BigQuery | BQ 무료 티어가 넉넉 | 벤더 종속적 스킬, 국내 목표 기업 스택과 거리 | 이점이 제한적 |
| 로컬 + 가격도 고정 테이블 | 가장 빠름 | "비용 숫자 어디서 났나" 질문에 무방비 | ADR-0004 위반. **치명적** |
| Kubernetes (kind/minikube) | 컨테이너 오케스트레이션 역량 | 구성 복잡도 급증, 본 문제와 무관 | 8주 예산에서 회수율 최악 |
| Databricks Community | 관리형 Spark 무료 | 외부 시스템 연동 제약, 전체 스택 재현 불가 | 파이프라인 전체를 담을 수 없음 |

## 결과

**얻는 것**
- 완전한 재현성 — 이 프로젝트의 최대 강점
- 비용 0원, 무기한 유지 가능
- 빠른 반복 속도

**포기하는 것**
- "AWS로 운영해봤다"는 직접 경험 주장
- 대규모 분산 처리 실증 (로컬 단일 노드 한계)

**보완책**
- AWS 이관 매핑표를 README에 명시
- 가격 수집 경로는 실제 AWS API 사용 → 클라우드 SDK 사용 경험은 확보
- 처리량 한계를 벤치마크로 측정해 정직하게 기록

## 재검토 조건

- 데이터 규모가 로컬 단일 노드로 처리 불가능한 수준으로 판명되면
  샘플링 전략을 도입하고 그 근거를 기록한다.
- 채용 과정에서 특정 클라우드 실증이 요구되면 별도 브랜치로 이관 데모를 만든다.
