# ADR-0002: Alibaba + Azure 두 트레이스를 사용한다

- **상태**: **부분 대체됨** — 워크로드 축은 ADR-0006, 절단 처리는 ADR-0007
- **일자**: 2026-09-14
- **갱신**: 2026-09-15 — Week 1 실측 결과 Azure 축과 `workload` 컬럼 가정이 모두 무너짐

## 배경

프로젝트에는 GPU 사용량 실측 데이터가 필요하다. 요구 조건은 다음과 같다.

1. **요청량과 실사용량이 모두 존재할 것** — 낭비를 계산하려면 둘 다 필요하다
2. 워크로드 유형(학습 / 추론)을 구분할 수 있을 것
3. 시계열 분석이 가능한 기간일 것
4. 공개되어 있고 재현 가능할 것

## 결정

두 데이터셋을 **병렬로** 사용한다. 합산하지 않는다.

| 데이터셋 | 역할 |
|---|---|
| Alibaba `cluster-trace-gpu-v2020` | 학습 / 배치 워크로드 축 |
| Azure `AzureLLMInferenceDataset` | 추론 서빙 워크로드 축 |

## 근거

### Alibaba를 선택한 이유

**`plan_gpu`(요청) 와 `gpu_wrk_util`(실사용) 이 둘 다 존재한다.**

이것이 결정적이다. 이 쌍이 없으면 "낭비"를 계산할 수 없고,
낭비를 계산할 수 없으면 이 프로젝트는 존재 이유가 없다.
그리고 이 갭은 **실측 데이터에만 존재한다** — 합성 데이터로는 만들 수 없다.

부수적 장점:
- `plan_gpu` 가 백분율이라 **GPU 분할 사용** 분석이 가능하다 (추론 서빙의 현실과 일치)
- job → task → instance 3계층 구조라 **자연스러운 차원 모델링 대상**이다
  (억지로 만든 조인이 아니라 데이터가 원래 그렇게 생겼다)
- 2개월치 → 주간 주기성 확보

### Azure를 추가한 이유

기사의 "24시간 상시 가동"은 사실상 **추론 서빙**이다.
Alibaba 2020 트레이스는 학습/배치 성격이 강해 이 축이 비어 있다.

두 축이 모두 있어야 다음 결론에 도달할 수 있다.

> "빌릴까 살까"는 조직 단위 질문이 아니라 **워크로드 단위 질문**이다.
> 학습은 간헐적이므로 스팟, 추론은 상시이므로 소유.

이것이 기사보다 한 걸음 더 나간 결론이며, 프로젝트의 차별점이다.

### 합산하지 않는 이유

두 트레이스는 **다른 조직, 다른 시점, 다른 인프라**다.
합산하는 순간 모든 숫자가 허구가 된다.

이 프로젝트가 보이려는 것은 "하나의 조직의 총비용"이 아니라
**"워크로드 유형에 따라 경제성이 갈린다"** 이므로, 병렬 비교로 충분하다.

## 검토한 대안

| 대안 | 장점 | 단점 | 기각 사유 |
|---|---|---|---|
| **Alibaba 단독** | 스코프가 좁아 완주 확률 최고 | 추론 축 부재 → 기사 논점과 어긋남 | 기사가 말하는 상시 가동 워크로드를 다루지 못함 |
| **Azure 단독** | 토큰 단위 원가에 집중, 트렌디 | 팀/사용자 차원이 약해 showback·차원모델링 역량 노출이 줄어듦 | **DE 역량 증명이라는 1차 목표에 불리** |
| Google Borg trace 2019 | 대규모, 신뢰도 높음 | GPU 정보가 제한적 | 요구 조건 1 미충족 |
| Microsoft Philly trace | 딥러닝 워크로드, GPU 사용률 포함 | 2017년으로 더 오래됨 | Alibaba 대비 이점 없음 |
| 합성 데이터 생성 | 원하는 패턴을 만들 수 있음 | **요청↔실사용 갭이 인위적** | 프로젝트의 핵심 근거가 허구가 됨. 치명적 |
| 실제 클라우드 계정에서 직접 수집 | 완전한 실측 | 비용 발생, 규모 부족, 8주 내 의미 있는 시계열 확보 불가 | 비현실적 |

## 결과

**얻는 것**
- 실측 기반의 낭비 정량화
- 워크로드별 차등 결론 — 기사를 넘어서는 인사이트

**포기하는 것**
- 데이터셋 2종 처리로 Week 1~3 작업량 약 1.3배 증가
- 두 소스의 이질성을 계속 설명해야 하는 부담

**감수하는 한계** (`docs/02-data-sources.md` 에 전부 명시)
- Alibaba는 2020년 V100/T4 세대
- 양쪽 모두 가격 정보 없음 (→ ADR-0004)
- Azure 트레이스 스키마 미검증

## 재검토 조건 — **발동됨 (2026-09-15)**

두 재검토 조건이 모두 발동되었다.

| 조건 | 결과 |
|---|---|
| Azure 트레이스 사용 불가 시 | **발동** — egress 정책 차단. 추론 축 제거 |
| `pai_group_tag_table` 로 분류 불가 시 | **발동** — 채움률 9.74%, 값은 모델명뿐 |

→ **ADR-0006** 이 워크로드 축을 재정의한다.
Alibaba 트레이스 채택 자체와 '합성 데이터 금지' 원칙은 그대로 유효하다.
