# 지표 사전 (Metric Dictionary)

- **문서 버전**: v1
- **상태**: 초안 — 컬럼 위치는 Week 1 스키마 실측 검증 후 확정
- **원칙**: 모든 지표는 **그레인(grain)**, **공식**, **원천 컬럼**, **알려진 함정**을 함께 정의한다.

> ⚠️ **검증 전 표기**: 아래 원천 컬럼의 *소속 테이블*은 Alibaba 트레이스 README 기준으로 작성했으나,
> 일부 컬럼(특히 `plan_gpu`)이 `pai_task_table` / `pai_instance_table` 중 어디에 있는지는
> 실제 파일로 확인해야 한다. Week 1 태스크 `verify-schema` 완료 시 이 경고를 제거한다.

## 0. 용어 정의

| 용어 | 정의 |
|---|---|
| **할당(allocated)** | 스케줄러에 요청되어 점유된 자원. 과금 대상. |
| **실사용(used)** | 실제로 연산에 쓰인 자원. |
| **낭비(waste)** | 할당되었으나 쓰이지 않은 자원. `allocated − used`. **돈은 여기서 샌다.** |
| **GPU-hour** | GPU 1장을 1시간 점유. 분할 사용 시 비례 배분 (0.5장 × 2시간 = 1 GPU-hour). |
| **가동률(utilization)** | `used / allocated`. 본 문서에서 별도 명시 없으면 이 정의를 쓴다. |

> **주의**: "가동률"은 업계에서 최소 3가지 뜻으로 쓰인다 —
> ① 할당 대비 실사용 ② 총 보유량 대비 할당 ③ 총 보유량 대비 실사용.
> 본 프로젝트는 ①을 기본으로 하되, L3 손익분기 계산에서는 ③을 쓴다.
> 혼동을 막기 위해 ③은 `fleet_utilization` 으로 별도 명명한다.

## 1. L1 — 진단 지표

### 1.1 `allocated_gpu_hours`

| 항목 | 내용 |
|---|---|
| **정의** | 스케줄러에 요청되어 점유된 GPU-시간 |
| **그레인** | (시간, 인스턴스) → 상위 집계 가능 |
| **공식** | `Σ (plan_gpu / 100.0) × duration_hours` |
| **원천** | `plan_gpu` (백분율: 50 = GPU 0.5장), 인스턴스 `start_time` / `end_time` |
| **함정** | `plan_gpu` 는 **백분율**이며 장수가 아니다. 100으로 나누지 않으면 100배 과대 계상된다. |
| **함정** | `end_time` 이 NULL/0 인 미완료 인스턴스 존재 → 트레이스 관측 종료 시점으로 절단(censoring) 처리하고 플래그를 남길 것 |

### 1.2 `used_gpu_hours`

| 항목 | 내용 |
|---|---|
| **정의** | 실제 연산에 사용된 GPU-시간 |
| **그레인** | (시간, 인스턴스) |
| **공식** | `Σ (gpu_wrk_util / 100.0) × duration_hours` |
| **원천** | `pai_sensor_table.gpu_wrk_util` |
| **함정** | 센서 값은 **인스턴스 생애 평균**일 가능성이 높다. 시간대별 프로파일이 필요하면 `pai_machine_metric` 을 교차 확인해야 한다. |
| **함정** | `gpu_wrk_util` 이 `plan_gpu` 를 **초과**하는 행이 존재할 수 있다(분할 GPU 초과 사용, 측정 오차). 클리핑하지 말고 **별도 플래그로 보존**한 뒤 데이터 품질 지표로 노출할 것. |

### 1.3 `gpu_waste_ratio` ⭐

| 항목 | 내용 |
|---|---|
| **정의** | 할당했으나 쓰지 않은 비율. **본 프로젝트의 핵심 지표.** |
| **그레인** | 임의 (팀 / 워크로드 / GPU 타입 / 일자) |
| **공식** | `1 − used_gpu_hours / NULLIF(allocated_gpu_hours, 0)` |
| **해석** | 0.6 이면 요청한 GPU의 60%가 놀고 있으며, 그만큼이 곧 비용이다 |
| **함정** | 분모가 0인 그룹 제외. 가중평균을 쓸 것 — 그룹별 비율의 단순 평균은 **심슨의 역설**에 빠진다. |

### 1.4 `waste_cost_krw` ⭐

| 항목 | 내용 |
|---|---|
| **정의** | 낭비의 금액 환산 |
| **그레인** | 임의 |
| **공식** | `(allocated_gpu_hours − used_gpu_hours) × price_per_gpu_hour_krw` |
| **원천** | 가격은 AWS Price List API (ADR-0004). 하드코딩 금지. |
| **함정** | 가격은 **GPU 타입별로 다르다.** 단일 평균 단가를 쓰면 고가 GPU의 낭비가 과소평가된다. 반드시 `dim_gpu_type` 조인 후 계산. |

### 1.5 `effective_cost_per_gpu_hour_krw` ⭐

| 항목 | 내용 |
|---|---|
| **정의** | **실사용** GPU-시간당 실질 단가 |
| **그레인** | 임의 |
| **공식** | `total_cost_krw / NULLIF(used_gpu_hours, 0)` |
| **해석** | 정가가 시간당 3,000원이어도 가동률이 40%면 실단가는 7,500원이다. **협상 테이블에 올라가는 숫자는 이것이다.** |
| **함정** | 분모가 실사용이므로 가동률이 극히 낮은 그룹에서 값이 폭발한다. 리포팅 시 `used_gpu_hours` 하한(예: 10 GPU-hour)을 걸 것. |

### 1.6 `cost_per_1k_tokens_krw` (추론 축)

| 항목 | 내용 |
|---|---|
| **정의** | 토큰 1,000개 처리 원가 |
| **그레인** | (시간, 모델/서비스) |
| **공식** | `total_serving_cost_krw / NULLIF((input_tokens + output_tokens) / 1000.0, 0)` |
| **원천** | Azure LLM Inference 트레이스의 입출력 토큰 수 |
| **함정** | 입력 토큰과 출력 토큰의 **연산 비용은 다르다** (prefill vs decode). 단순 합산은 1차 근사이며, 이 한계를 리포트에 명시할 것. |

### 1.7 `fleet_utilization`

| 항목 | 내용 |
|---|---|
| **정의** | 보유(또는 임대) GPU 총량 대비 실사용 비율 |
| **그레인** | (시간, GPU 타입) |
| **공식** | `used_gpu_hours / (gpu_count × elapsed_hours)` |
| **용도** | **L3 손익분기 판정의 입력값.** `U*` 와 직접 비교되는 값은 이것이다. |
| **함정** | §0의 "가동률" ①과 혼동 금지. 온프레미스는 놀고 있는 GPU도 비용이 나가므로 분모가 보유량이어야 한다. |

## 2. L2 — 예측 지표

### 2.1 예측 대상

| 대상 | 그레인 | 비고 |
|---|---|---|
| `demand_gpu_hours` | 시간별 | 1차 예측 대상 |
| `demand_tokens` | 시간별 | 추론 축 |
| `spot_price` | 시간별, 인스턴스 타입별 | AWS Spot Price History가 실측 시계열 |

### 2.2 평가 지표

| 지표 | 용도 | 선택 이유 |
|---|---|---|
| **WAPE** | 주 보고 지표 | MAPE는 수요가 0에 가까운 구간에서 발산한다. GPU 수요는 야간에 0에 근접하므로 MAPE 부적합. |
| **Pinball Loss** | 분위수 예측 평가 | 용량 조달은 P90 기준으로 하므로 점 예측 손실로는 평가할 수 없다 |
| **P90 Coverage** | 구간 신뢰성 | 실제값이 P90 아래에 떨어지는 비율이 0.9에 근접하는가 |

### 2.3 베이스라인 (필수)

| 베이스라인 | 정의 |
|---|---|
| `naive` | 직전 시각 값 |
| `seasonal_naive_168h` | 168시간(1주) 전 같은 시각 값 ← **주 베이스라인** |
| `moving_average_24h` | 최근 24시간 이동평균 |

> **ADR-0005**: 머신러닝 모델은 `seasonal_naive_168h` 를 WAPE 기준으로
> **유의미하게 이겼을 때만** 채택한다. 이기지 못하면 베이스라인을 채택하고 그 사실을 기록한다.

## 3. L3 — 처방 지표

### 3.1 `onprem_tco_annual_krw`

| 항목 | 내용 |
|---|---|
| **정의** | 온프레미스 GPU 인프라의 연간 총소유비용 |
| **공식** | `capex_annualized + power + cooling + maintenance + labor + space + network` |
| **원천** | `config/tco.yaml` — **전부 가정값이며 민감도 분석 대상** |

세부:

```
capex_annualized = 장비가 / 감가상각연수
power            = gpu_count × tdp_kw × pue × utilization_factor × 8760 × 전력단가
maintenance      = 장비가 × 유지보수율
labor            = (gpu_count / 엔지니어당_관리_gpu수) × 인건비
```

> **`power` 의 `utilization_factor` 주의**: GPU는 유휴 시에도 전력을 소비한다.
> TDP × 100% 로 계산하면 과대, 유휴 전력을 무시하면 과소 계상된다.
> `config/tco.yaml` 의 `idle_power_ratio` 로 명시적으로 모델링한다.

### 3.2 `breakeven_utilization` (`U*`) ⭐⭐

| 항목 | 내용 |
|---|---|
| **정의** | 온프레미스가 클라우드보다 유리해지는 최소 `fleet_utilization` |
| **공식** | `onprem_tco_annual_krw / (ondemand_price_per_hour_krw × 8760 × gpu_count)` |
| **해석** | `fleet_utilization > U*` 이면 **소유**, 아니면 **임대** |
| **용도** | **프로젝트의 최종 산출물.** 기사 질문에 대한 직접적인 답. |
| **함정** | 분자·분모 모두 GPU 타입에 의존한다. 반드시 동일 타입(또는 명시적 성능 환산) 기준으로 비교할 것. |
| **함정** | `U* > 1` 이 나올 수 있다 → "어떤 가동률에서도 클라우드가 유리"라는 유효한 결론이며 버그가 아니다. |

### 3.3 `breakeven_months`

| 항목 | 내용 |
|---|---|
| **정의** | 주어진 가동률에서 온프레미스 누적 비용이 클라우드 누적 비용을 밑돌기 시작하는 시점 |
| **공식** | 월별 누적 비용 곡선의 교차점 (해가 없으면 NULL) |
| **검증 대상** | 기사의 "풀 가동 시 약 1년 반" 주장과 대조한다 |

### 3.4 `procurement_mix`

| 항목 | 내용 |
|---|---|
| **정의** | 예측된 수요 분포 하에서 총비용을 최소화하는 조달 조합 |
| **출력** | `{온프레미스 N장, 예약 M장, 온디맨드 가변, 스팟 가변}` |
| **제약** | 추론 워크로드는 스팟 배정 불가 (중단 불가 요구사항) |
| **입력** | L2의 **P50이 아니라 P90** 수요 — 평균으로 조달하면 절반의 시간 동안 부족하다 |

## 4. 데이터 품질 지표

파이프라인이 스스로를 감시하기 위한 지표. dbt 테스트로 강제한다.

| 지표 | 임계 | 실패 시 |
|---|---|---|
| `pct_instances_missing_end_time` | 관측 후 임계 확정 | 경고 + 절단 플래그 |
| `pct_util_exceeds_plan` | 관측 후 임계 확정 | 경고, 클리핑 금지 |
| `pct_jobs_without_sensor_data` | 관측 후 임계 확정 | 낭비 지표 신뢰구간에 반영 |
| `price_data_freshness_hours` | > 48 시간 | DAG 실패 |
| `orphan_task_without_job` | > 0 건 | DAG 실패 (참조 무결성) |

> 임계값을 **관측 전에 정하지 않는다.** Week 1 프로파일링 결과를 보고 확정하며,
> 그 근거를 이 문서에 기록한다.
