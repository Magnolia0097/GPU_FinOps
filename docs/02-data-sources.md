## 1. Alibaba `cluster-trace-gpu-v2020` — 학습/배치 축

**출처**: https://github.com/alibaba/clusterdata/tree/master/cluster-trace-gpu-v2020
**논문**: *MLaaS in the Wild: Workload Analysis and Scheduling in Large-Scale Heterogeneous GPU Clusters* (NSDI '22)

### 1.1 규모 (README 확인 완료)

| 항목 | 값 |
|---|---|
| 기간 | 2020년 7월 ~ 8월 (약 2개월) |
| GPU | 6,500개 이상 |
| 머신 | 약 1,800대 |
| GPU 모델 | V100M32, T4, MISC(K40m, K80, M60) |

### 1.2 테이블

| 테이블 | 내용 |
|---|---|
| `pai_job_table` | 작업 제출 정보 |
| `pai_task_table` | 태스크 실행 정보 |
| `pai_instance_table` | 인스턴스 실행 정보 |
| `pai_sensor_table` | 인스턴스 리소스 **센서 데이터 (실사용)** |
| `pai_group_tag_table` | 인스턴스 의미론적 정보 (워크로드 분류에 사용) |
| `pai_machine_spec` | 머신 사양 |
| `pai_machine_metric` | 머신 리소스 지표 |

### 1.3 핵심 컬럼 — 이 데이터셋을 선택한 이유

| 구분 | 컬럼 | 단위 |
|---|---|---|
| **요청** | `plan_cpu` | 백분율 (600 = 6 vCPU) |
| **요청** | `plan_gpu` | 백분율 (**50 = GPU 0.5장**) |
| **요청** | `plan_mem` | GB |
| **실사용** | `gpu_wrk_util` | 백분율 |
| **실사용** | `cpu_usage` | 백분율 |
| **실사용** | `avg_mem` / `max_mem` | GB |
| **실사용** | `avg_gpu_wrk_mem` / `max_gpu_wrk_mem` | GB |

> **`plan_gpu` ↔ `gpu_wrk_util` 쌍이 존재한다는 것이 이 트레이스를 선택한 결정적 이유다.**
> "요청했지만 쓰지 않은 GPU" = 낭비 = 돈. 이 갭은 실측 데이터에만 존재하며
> 합성 데이터로는 만들 수 없다. 프로젝트 전체가 이 한 쌍의 컬럼 위에 서 있다.

또한 `plan_gpu` 가 백분율이므로 **GPU 분할 사용(fractional GPU)** 분석이 가능하다.
이는 추론 서빙의 현실적 운영 방식과 일치한다.

### 1.4 알려진 한계 (숨기지 않는다)

| 한계 | 영향 | 대응 |
|---|---|---|
| **가격 정보 없음** | 비용을 직접 계산 불가 | §3의 실측 가격 API와 조인 |
| **2020년 데이터, V100/T4 세대** | 현행 H100/A100과 성능·가격이 다름 | GPU 타입을 차원(dimension)으로 분리하고 `config/gpu_mapping.yaml` 로 명시적 환산. 매핑 근거를 문서화 |
| **2개월치 → 계절성 부족** | 월간/분기 주기 학습 불가 | 예측 대상 주기를 **일간·주간까지로 한정**하고 명시 |
| **단일 기업(알리바바 PAI) 워크로드** | 일반화 한계 | 결론을 "모든 조직"이 아니라 "이 워크로드 특성에서는"으로 한정 서술 |
| **익명화된 사용자/팀 식별자** | 실제 조직 구조 반영 불가 | showback은 구조 시연 목적임을 명시 |

### 1.5 라이선스

저장소 라이선스 조건을 확인하고 준수한다. 원본 데이터는 저장소에 커밋하지 않으며
(`data/` 는 `.gitignore` 처리), 다운로드 스크립트만 버전 관리한다.

### 1.6 Week 1 검증 태스크

- [ ] `plan_gpu` 의 소속 테이블 확정 (`pai_task_table` vs `pai_instance_table`)
- [ ] job → task → instance → sensor 조인 키 확정
- [ ] `pai_group_tag_table` 로 워크로드 유형(학습/추론/기타) 분류 가능 여부 확인
- [ ] `end_time` 결측률 측정 → 절단 처리 기준 확정
- [ ] `gpu_wrk_util > plan_gpu` 발생률 측정 → 데이터 품질 임계 확정

### 2.2 선택 이유

기사가 말하는 "24시간 상시 가동"은 사실상 **추론 서빙**이다.
알리바바 2020 트레이스는 학습/배치 성격이 강해 이 축이 비어 있다.
두 트레이스를 합쳐야 "학습은 스팟, 추론은 소유"라는 **워크로드별 차등 결론**에 도달할 수 있다.

### 2.3 알려진 한계

| 한계 | 대응 |
|---|---|
| 정확한 컬럼 스키마 미검증 (타임스탬프 필드 존재 여부 포함) | **Week 1 최우선 검증 태스크.** 불일치 시 ADR-0002 개정 |
| 토큰 수만 있고 GPU 사용량·지연시간 없음 | 토큰 → GPU-시간 환산 모델이 필요. 환산 계수를 `config/` 에 노출하고 민감도 분석 |
| prefill(입력)과 decode(출력)의 연산 비용이 다름 | 1차는 단순 합산, 한계 명시. 여유 시 가중 모델로 확장 |
| 알리바바와 시점·조직이 다름 | 두 축을 **합산하지 않는다.** 워크로드 유형별로 **병렬 비교**만 수행 |

> ⚠️ **두 트레이스를 하나의 클러스터인 것처럼 합치지 말 것.**
> 출처가 다른 데이터를 합산하면 그 순간 모든 숫자가 허구가 된다.
> 이 프로젝트는 "워크로드 유형별로 경제성이 다르다"를 보이는 것이지
> "하나의 조직 비용"을 재현하는 것이 아니다.

## 3. 가격 데이터 — 실측 API

> **원칙: 가격은 하드코딩하지 않는다.**
> "그 비용 숫자 어디서 나왔나요?"가 면접 첫 질문이 될 것이기 때문이다. (ADR-0004)

| 소스 | 내용 | 인증 |
|---|---|---|
| **AWS Price List Bulk API** | 온디맨드 · 예약 정가 | 불필요 (공개 JSON) |
| **AWS `describe_spot_price_history`** | **실제 스팟 가격 변동 이력** | AWS 자격증명 필요 (조회 자체는 무료) |
| 국내 CSP 공개 요금표 | 원화 기준 비교축 | 수동 수집 + 출처·수집일 기록 |

### 3.1 스팟 가격의 이중 역할

`describe_spot_price_history` 는 단순 가격표가 아니라 **진짜 시계열**이다.
따라서 두 가지로 쓴다:

1. 비용 계산의 입력값
2. **L2 예측의 두 번째 예측 대상** — 실측 시계열이므로 모델 검증에 이상적

### 3.2 한계

| 한계 | 대응 |
|---|---|
| **가격 수집 시점 ≠ 트레이스 시점** | 비용 **절대값**을 주장하지 않는다. 산출물은 **상대 비교와 손익분기점**이다 |
| 스팟 이력은 90일만 제공 | 장기 분석 불가를 명시. 수집분을 누적 적재해 향후 확장 |
| 리전·AZ별 가격 상이 | 리전을 명시적 차원으로 모델링 |
| 환율 변동 | `config/tco.yaml` 의 `usd_krw` 로 단일 지점 관리, 민감도 분석 포함 |

## 4. 온프레미스 TCO 가정 — `config/tco.yaml`

API로 얻을 수 없는 유일한 영역이며, **따라서 가장 정직해야 하는 영역**이다.

규칙:

1. 모든 값은 `config/tco.yaml` 한 곳에만 존재한다. 코드에 숫자를 박지 않는다.
2. 모든 값에 `source` 와 `confidence` 를 붙인다.
3. `confidence: low` 인 값은 **전부 민감도 분석 대상**이다.
4. 결과 리포트는 단일 숫자가 아니라 **범위**로 제시한다.

> 면접관은 숨긴 정밀함보다 드러낸 가정을 높게 평가한다.
> "이 값이 ±30% 흔들리면 결론이 뒤집히는가?"에 답할 수 있어야 한다.

## 5. 데이터 취급 규칙

| 규칙 | 이유 |
|---|---|
| 원본 데이터는 커밋하지 않는다 (`data/` → `.gitignore`) | 용량 · 라이선스 |
| 다운로드는 `scripts/` 의 스크립트로 재현한다 | 재현성 |
| AWS 자격증명은 환경변수로만 주입한다 | 저장소에 비밀정보를 남기지 않는다 |
| 수집한 가격 데이터는 **수집 시각과 함께** 적재한다 | 시점 추적성 |
